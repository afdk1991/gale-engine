> 适用范围：每次发版（含 `v0.x` 小版本）前的质量门禁。
> 说明：自动化门禁（typecheck / vitest / 构建 / 核心 PowerShell 命令直测）已在本机通过；GUI 交互项标注「⚙️ 需 Windows 实机」，由发布人在真实 Windows 上执行。

- [ ] `npm run test`（`vitest run`）全绿（当前 **498 项 / 29 个文件**）
- [ ] `npm run build`（`electron-vite build`）主进程/预加载/渲染产物均生成，无报错
- [ ] 版本号 `package.json#version` 与计划发版号一致（当前 `0.1.10`；下次发版应为 **`0.1.11`**）
- [ ] 全量代码审查遗留项已清零：`docs/code-review-2026-09-16.md` §〇「修复进度」表中 **H1 / M1–M10 / L1–L12 全部为 ✅**

### 诚实回执与注入防护（本轮加固，服务层直测）

- [ ] **严格回执解析**：错误信息中含 "OK" 字样（如 `ERR:xxx OK?`）时判定为**失败**；输出为空时判定为**失败**（不得因空字符串而通过）
  - 判定规则：`ERR:` 优先；`OK` 必须**独立成行**。已覆盖 `process.ts` / `firewall.ts` / `tasks.ts` / `winservices.ts` / `toolbox.ts` / `optimizer.ts`
- [ ] **清空回收站**：无权限/失败时返回 `ERR:` 并如实报错，**不得**因 `-ErrorAction SilentlyContinue` 而无条件输出 OK
- [ ] **启动项禁用可逆**（L8）：禁用后该项仍留在列表中（Windows 注册表值置 `Hidden=true`，macOS plist `Disabled`，Linux `.desktop` 加 `Hidden=true`），再次点击「启用」可原地恢复，无需手动补命令
- [ ] **启动项名称白名单**（L4）：name / location 含 `$(…)`、引号、换行等注入型输入时被拒绝，且不进入脚本
- [ ] **`.desktop` 转义**（L9）：`Exec=` 中的路径含引号 / `$` / 反引号时被转义，生成的 `.desktop` 仍可被桌面环境正常解析
- [ ] **游戏模式还原凭据白名单**（L12）：Windows 电源计划 GUID、Linux governor、macOS caffeinate PID 均需通过格式校验；非法值返回 `ERR:还原凭据非法` 且**不回显原始输入**
- [ ] **macOS 还原探活**：PID 对应进程已退出时 `kill -0` 探测后按**成功**处理（不把「进程已退出」误报为失败）
- [ ] **还原失败保留凭据**：还原失败时 `KEY_PREVIOUS` / `KEY_BOOSTED` / caffeinate PID 均**保留**，便于重试；仅成功时清除
- [ ] **提权临时文件清理**（L7）：正常路径下 `%TEMP%` 中 `gale-elevate` 前缀的脚本/输出文件执行后被删除；人为中断（UAC 无响应）后重新启动应用，**超过 1 小时**的陈旧残留被清理，近期文件不被误删
- [ ] **ping 丢包率 clamp**（L11）：0–100 范围外数值被夹紧；丢包 100% 时 `ok=false`（不因脚本自称 ok 而翻转）

## 五、Release 发布（CI tag 触发 + 本地备用通道）

### CI 自动发布（⚙️ GitHub Actions）
- [ ] 推送 `v*` tag 触发 `.github/workflows/release.yml`，工作流 `completed / success`
- [ ] Release 产物齐全：`gale-engine-${version}-x64-setup.exe` / `-arm64-setup.exe` + 各自 `.blockmap` + `latest.yml`（macOS 为 `.dmg`，Linux 为 `.AppImage` / `.deb`）
- [ ] `latest.yml` 内文件名与实际产物名一致（ASCII，避免净化名导致自动更新 404）
- [ ] **Release 说明非空**：body 含本版本功能条目 + 下载表（由 `scripts/extract-changelog.py` 从 CHANGELOG 对应章节生成）
  - ⚠️ 历史坑：曾用 `generate_release_notes`，无 PR 时只产出一行 `Full Changelog` 链接 → body 近乎空，而 `electron-updater` 把 body 当更新弹窗内容，导致用户点「检查更新」看不到任何说明

- [ ] **Latest 归属正确**：`gh release list` 中最新版本为 `Latest`（补发/重建旧版本后易被旧版本抢走，修正：`gh release edit <tag> --latest`）

- [ ] **各平台更新元数据齐全**：`latest.yml`（win）、`latest-mac.yml`（mac，需 zip 产物）、`latest-linux.yml` / `latest-linux-arm64.yml`（linux）；缺任一份即该平台自动更新失效
- [ ] 仓库 Actions 权限已启用（Settings → Actions → Allow all actions）

### 本地备用通道（CI 不可用时）
